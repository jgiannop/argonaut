# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Argonaut is a cross-platform (Linux, Windows, macOS) desktop file manager written in C++17 with Qt 6 Widgets. It has to keep working on all three platforms, so use Qt APIs (`QStorageInfo`, `QStandardPaths`, `QDesktopServices`, `QFile::moveToTrash`, etc.) instead of OS-specific calls. Where OS-specific behaviour is unavoidable, put it behind `Q_OS_LINUX` / `Q_OS_WIN` / `Q_OS_MACOS` guards, as `Sidebar::refresh()` does.

The minimum Qt version is **6.4** (what Ubuntu 24.04 ships). Don't use APIs added after 6.4 unless you also raise `find_package(Qt6 6.4 ...)` in `CMakeLists.txt`.

License: GPL-3.0-or-later (`LICENSE`), copyright johngiannop. Hosted at https://github.com/jgiannop/argonaut (`origin`). `.github/workflows/ci.yml` builds and runs the tests on Ubuntu 24.04 for every push and PR; pushing a tag `vX.Y.Z` that matches `project(argonaut VERSION …)` runs `release.yml`, which builds the .deb and publishes a GitHub Release with it. A `.deb` comes from CPack: `cmake --preset package` (Release, prefix `/usr`, no tests), `cmake --build build/package`, `cpack --config build/package/CPackConfig.cmake`. Library dependencies come from dpkg-shlibdeps (so a package built on Ubuntu 24.04 needs 24.04's t64 libraries); optional helpers are `CPACK_DEBIAN_PACKAGE_RECOMMENDS`.

## Build and run

CMake presets (`CMakePresets.json`) use the Ninja generator and build into `build/<preset>`:

```bash
cmake --preset debug            # configure (or: --preset release)
cmake --build build/debug       # build
./build/debug/argonaut [path]  # run; optional start folder (path or file:// URL)
```

The `debug` preset builds with `-Wall -Wextra -Wshadow=local` (not as errors) and **the build is free of warnings: keep it so** (a variable that hides another of the same name, an unused function). In VS Code, CMake Tools is set to use the presets. F7 builds and F5 debugs with gdb (`.vscode/launch.json` runs the `CMake: build` task first).

Linux dependencies: `cmake ninja-build qt6-base-dev qt6-tools-dev designer-qt6 qt6-wayland libvterm-dev libarchive-dev libqscintilla2-qt6-dev`. `libqscintilla2-qt6-dev` is optional ("Code editor: disabled"; found with `find_path`/`find_library`, it has no CMake or pkg-config file; `ARGONAUT_QSCINTILLA`): without it Edit in Preview is a plain text box. `libarchive-dev` is optional too ("Compress / Extract: disabled"; `src/FileJobArchive.cpp` is then left out, `ARGONAUT_ARCHIVES` undefined, `FileJob::archivesSupported()` returns false and the UI hides the actions, and `tst_archives` isn't built). `libvterm-dev` is optional: without it, CMake prints "Embedded terminal: disabled" and the app builds without the terminal panel, with all terminal code behind `#if defined(ARGONAUT_TERMINAL)`. If you add the terminal sources to a stale build directory and the linker reports missing `TerminalWidget` vtable/metaObject symbols, delete `build/debug/argonaut_autogen` and rebuild.

Tests (Qt Test + CTest, in `tests/`). They run headless and sandbox `HOME` and the trash. **`ARGONAUT_TRASH_HOME_ONLY=1` must be set for anything that runs trash code in tests:** without it, `Trash::filesDirs()` also finds the `.Trash-<uid>` folders on real mounted drives, and Empty Trash would delete them. `tst_fileoperations` sets it in `main()` and `tests/CMakeLists.txt` sets it for ctest. Tests also point `HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` at a temporary folder (and `tst_thumbnailer` sets `XDG_DATA_DIRS` to fake thumbnailers), so the real bookmarks file and settings are never touched. Anything that drives a real window in a test must set `ARGONAUT_EJECT_PROGRAM` and `ARGONAUT_GIO_PROGRAM` to fake scripts, so it never ejects a real drive, launches real apps, or changes default apps (`tst_mainwindow`'s `main()` does all of this; copy it).

Shared test code is `tests/TestSupport.h`: `TestSupport::writeScript(path, text)` (a pretend program for an `ARGONAUT_*_PROGRAM` variable), `TestSupport::Sandbox` (first line of `main()`, before the application object: private HOME/XDG folders, `ARGONAUT_TRASH_HOME_ONLY`, `ARGONAUT_KEYSTORE=file`, offscreen) and `TestSupport::waitForJob(ops)`, which **fails the test when a job never finishes** (the old per-file copies only warned, so a hung job looked like one without errors). New tests go in `tests/CMakeLists.txt` as one line, `argonaut_test(<name> [LIBRARY argonaut_app] [TIMEOUT s] [PRIVATE_BUS] [ENV …] [SOURCES …])`, which also gives every test the safe environment. Older test files still set up their own sandbox in `main()`; use `TestSupport` when you touch them.

Window tests (`tests/tst_mainwindow.cpp`): the real `MainWindow`, headless (`offscreen`), for the decisions between the user and the file engine: Delete trashes only the selection and undoes; Shift+Delete, Delete inside the Trash and Empty Trash ask first and Cancel changes nothing; Analyze turns file commands off; a read-only folder allows only Copy; a cut is pasted once; `dropActionFor`'s rules; a drop on the Trash trashes; split view acts on the active pane; the Open/Save window answers once and asks before replacing. `TestMainWindow` is a `friend` of `MainWindow`, so tests trigger the real `QAction`s and read private members. `answerNext("Cancel")` presses a button in the next `QMessageBox` (a timer watches `QApplication::activeModalWidget()`). **When you add a command that deletes, moves or overwrites, add its test here**, and check the test fails when the safety check is removed (the first set was verified that way). The app's sources except `main.cpp` are the static library `argonaut_app`, which the executable and this test link.

Memory-error checks: `cmake --preset sanitize && cmake --build build/sanitize && ctest --preset sanitize` builds everything with AddressSanitizer + UBSan (`-fno-sanitize-recover=all`, leak detection off: Qt and fontconfig keep memory until exit). CI runs it as its own job on every push. Don't cast a `QEvent` to a subclass before checking `type()`: UBSan stops on it (`PathBar::eventFilter` did).

```bash
ctest --preset debug                                    # all tests
./build/debug/tests/tst_fileoperations copyFolderTree   # one test function
```

In VS Code, CMake Tools' Testing panel runs them too. Formatting: `.clang-format` (Qt-like). Format-on-save applies to changed lines only. There is no linter.

## Architecture

- `qt_standard_project_setup()` turns on AUTOMOC/AUTOUIC. Every new source or header must be listed in `CMakeLists.txt`, or moc won't run on it. The GUI goes in `qt_add_library(argonaut_app STATIC ...)` (the executable is only `main.cpp` on top of it). The folder model (`DirectoryModel`), the disk-usage tree (`DiskUsageModel`), the Trash, bookmark and Open With helpers (`Trash`, `Bookmarks`, `OpenWith`) and the file-operations engine (`FileJob`, `FileOperations`, plus `FileJobArchive.cpp` when libarchive is found) are the static library `argonaut_core`, which both the app and `tests/` link against. Keep it free of window/widget code so it stays testable.
- Real file types (`src/ContentType.{h,cpp}`, in `argonaut_core`): this is deliberately **stricter than Nautilus/GIO**, which trust any extension only one type uses.
  - `inspect()` reads the first 4 KiB and calls `judge(byName, byContent)`. The verdicts are Consistent, Identified (no usable name), Mismatch, and Dangerous (`isProgram(content)` while the name isn't a program).
  - Rules that prevent false alarms:
    - Generic or empty content (`application/octet-stream`, `x-zerosize`) is never a mismatch.
    - Related types (`inherits`, e.g. docx is a zip) agree with each other.
    - Two text types never count as a mismatch, because sniffing can't tell Markdown from Python.
  - A read-only scan of a real 749-file Downloads folder gave 0 false alarms and caught 1 real mismatch.
  - `DirectoryModel` applies cached verdicts while listing (`applyCachedContent`) and reads the rest on `m_contentPool` (1 thread). Reading starts only **after** the listing is done, so it never competes with it.
  - On local disks every file is checked; on removable and network drives (`m_thorough == false`) only files whose data the views ask for, i.e. the visible ones.
  - Results go to `ContentType::Cache`: QDataStream at `QStandardPaths::CacheLocation/content-types.bin`, keyed by path, size and mtime, at most 200k entries, saved 3 s after changes and on quit.
  - The effective type (`mimeFor`) is the content type for Identified, Mismatch and Dangerous. `nameMimeFor` is the name-only type. The roles are `VerdictRole`, `NameMimeRole`, `ContentMimeRole` and `Qt::ToolTipRole`.
  - UI: `FileItemDelegate::paintContentBadge` (amber for Mismatch, red for Dangerous).
    - `MainWindow::openFile` warns about Dangerous files and never runs them, and opens Mismatch/Identified files with the default app for the real type.
    - `fixExtension` ("Rename to …") is undoable, and Properties shows "Name says" against the real type.
  - Tests set `XDG_CACHE_HOME`; `ContentType::readCount()` lets them prove that a second visit reads nothing.
- **Painting asks the model for every cell's text, every time**, so those must be cheap. The Modified column wasn't: three conversions to local time a cell, each a `stat` of `/etc/localtime` by glibc (5 µs and 3 system calls a cell). `DirectoryModel::dateText()` now asks what day it is at most once a second and keeps the texts by the second they are for (`m_dateTexts`, cleared at midnight and at 20,000): 0.3 µs. `tst_directorymodel bigFolder` prints each column's cost per cell and `modifiedColumnText` checks what is shown; `tst_mainwindow paintingABigFolderIsQuick` and `tst_tui drawingABigFolderIsQuick` print a paint's and a frame's time in a 3,000-file folder (bounds far above what it takes: they catch something badly wrong, not a small drift). **`strace -c -e trace=newfstatat` on a test is how the hidden system calls were found**; `perf` isn't allowed on this machine.
- Performance guards in `DirectoryModel`: each batch of a big listing is sorted on its own and **merged** (`resort(sortedPrefix)`), not re-sorted in full. `m_rowByPath` is rebuilt lazily (`rebuildIndex()` only marks it stale; readers call `ensureIndex()`). `FileEntry::fullPath` is built once (`setDir`). Re-run the A/B benchmark if you touch these (`tst_directorymodel bigFolder`, release build): 20,000 files should load fully in about 0.14 s.
  - `makeEntry` does **one `lstat` per file** (plus a `stat` for symlinks) on Unix, not `QFileInfo`. `QFileInfo::lastModified()` converts to local time, and glibc stats `/etc/localtime` twice per call, which tripled a listing's system calls (0.20 s → 0.14 s when removed). Don't call `lastModified()` or `isWritable()` (one `access()` each) per file while listing; check with `strace -c`.
- Small shared helpers — use these, don't write another copy:
  - `Tools::program(variable, name)` / `Tools::find(...)` / `Tools::gio()` (`src/Tools.h`): every outside program and its `ARGONAUT_*_PROGRAM` test override.
  - `Naming::naturalCollator()`, `Naming::isHiddenName(name)`, `Naming::hasHiddenPart(relativePath)`.
  - `tildePath(path)` (`src/Format.h`): a folder for display with `~` for home.
  - `statMtimeMs(st)` (`src/StatTime.h`): mtime from `stat()`; the field is named differently on macOS.
  - `Sandbox::systemArgs()`: the bubblewrap arguments every box starts with (the thumbnailer adds its own to them).
  - `DirectoryModel::contentResult(index)`: an item's real-type verdict from its roles.
  - In `MainWindow`: `selectedFiles()`, `selectionIsStarred()`, `launchWith(app, files)`.
- Sizes: always use `formatSize()` (`src/Format.h`). It gives powers of 1000 with kB/MB/GB, like GNOME and drive labels; never call `QLocale::formattedDataSize`'s default, which gives KiB/MiB.
- Natural name order uses `QCollator` in numeric mode. In the "C"/POSIX locale Qt can't do numeric collation, so `Naming::naturalCollator()` uses English rules there; keep that, or `LANG=C` users get "file10" before "file2".
- The look copies GNOME Files (Nautilus) / libadwaita, but it's built only from Qt, so it looks the same on every platform:
  - `Theme` (`src/Theme.{h,cpp}`) holds the light and dark colour tokens, chosen from `QApplication::palette()`. Use the application palette, not the widget palette: our own style sheet changes widget palettes.
  - `glyphIcon(Glyph, color)` draws every UI icon in code through a custom `QIconEngine`. Don't depend on the system icon theme or the Qt SVG plugin for UI icons. File-type icons come from the OS through `QFileIconProvider` (cached per mime type by `DirectoryModel`).
  - Themes (`ThemeMode`: Follow System, Light, Dark, Midnight Blue, Rosé Dawn, Forest, Sunset) are chosen in `PreferencesDialog` and saved with `QSettings` under `appearance/theme` (keys are in `kThemes` in `Theme.cpp`).
    - Light and Dark use libadwaita's exact colours (`adwaita()`). The named themes are built by `custom()` from four base colours (window, sidebar, text, accent), and every other token is derived from those.
    - `applyThemeMode()` sets `QApplication`'s palette (`paletteFor(theme)`). Follow System keeps or restores the platform palette that was captured at startup.
    - `currentTheme()` returns the applied tokens. `MainWindow::applyTheme()` re-styles only when `Theme::id` changes.
    - To add a theme: add a `ThemeMode` value, a `kThemes` entry and a case in `Theme::forMode`. Preferences picks it up automatically.
    - **Themes from files** (`docs/themes.md` is the guide for people writing one): a theme is also a JSON file in a themes folder (`userThemesFolder()` = `$XDG_DATA_HOME/argonaut/themes`, then `<program folder>/themes` and the system data dirs' `argonaut/themes`; `data/themes/*.json` are the two that come along; `ARGONAUT_THEMES_PATH` replaces all of them and tests set it empty). The public API is **by key**: `allThemes()` (the built-in ones, then the valid files by name), `savedThemeKey()` / `setThemeKey()` / `applyThemeKey()` / `currentThemeKey()` / `themeForKey()`; a file's key is `file:<file name without .json>` (a plain name: `fileOfKey` refuses anything else). `readThemeFile` needs `window`, `text` and `accent`, takes `sidebar`, `name`, `dark` and any other token as an override, and builds the rest with `custom()`; its `Theme::id` holds a hash of the file, which is what makes `MainWindow::applyTheme` re-style. `ThemeWatcher` watches the folders and the applied file: saving it re-applies (a file broken mid-edit keeps the last good colours; a file that is gone falls back to Follow System; when only non-palette colours changed, windows are sent `ApplicationPaletteChange` by hand). `saveThemeFile` writes the current theme with every token spelled out, never over an existing file (Preferences → "Save This Theme as a File…", which also shows it in the file window through `PreferencesDialog::folderRequested`).
    - Where themes are chosen: the Preferences cards, **View → Theme** (`m_themeMenu`, filled by `fillThemeMenu` when it opens) and therefore the command palette (`showCommandPalette` fills that menu before it walks the menus, as it does for New Document). `tst_mainwindow themesFromFiles`.
  - `MainWindow::applyTheme()` builds one window-wide style sheet (`styleSheetFor`, using `@token` placeholders) and re-creates every themed icon. It runs again on `ApplicationPaletteChange`. Anything with a themed icon must be updated there.
- Window chrome: on Linux and Windows the window is frameless (client-side decorations). Set `ARGONAUT_NATIVE_DECORATIONS=1` to turn that off; macOS always uses the native frame.
  - Two `HeaderBar`s, one above the sidebar and one above the content, act as the title bar. Dragging empty space calls `startSystemMove`; double-click maximises.
  - Edge resizing is handled by an event filter on the `QWindow` (`MainWindow::eventFilter` → `startSystemResize`).
  - The window buttons only exist when `m_csd` is true. They sit at the right end of the menu bar row (`menuRow`: the `QMenuBar` stretched, then `addWindowButtons`), not in the header bar. `menuRow` carries the bottom border, so it runs under the buttons too. The row itself drags and maximises as well (`m_menuRow` shares the menu bar's event-filter branch): a `QMenuBar` whose menus are hidden (Open/Save windows) is only ~2 px tall, so drags that relied on the bar alone worked only on that band.
- Main view:
  - `DirectoryModel` is a flat table model (Name/Size/Type/Modified) of one folder. Don't go back to `QFileSystemModel`, which was ~5x slower on big folders and couldn't keep folders-first natural order.
    - `setPath()` lists the folder on a worker thread, using a generation counter to drop stale results. Big folders arrive in batches (the first after 15 ms). `loaded` fires when the listing is complete.
    - Each entry is stat-ed once while listing, so painting never touches the disk. Mime type, icon and type name are worked out from the name on demand and cached. Symlinks get their target's icon: Qt's provider gives every link a generic link icon, which the per-mime cache would then reuse for real files.
    - Access (`src/Access.{h,cpp}`, core): the same stat keeps the owner/group/other bits (`FileEntry::permissions`, never Qt's "User" bits, which cost an `access()` each), `ownerId`, `groupId` and `brokenLink`.
      - `LockedRole` (`Access::likelyWritable`, in memory) draws 🔒 at the icon's top-left and `SymLinkRole` an arrow at the bottom-left (`FileItemDelegate::paintAccessBadges`). Tooltips add "Read-only (owner: …)" and "Link to …" (readlink only on hover).
      - Owner, Group and Permissions (`-rw-r--r--`; a link shows its target's) are columns 4–6, hidden unless ticked in the list header's right-click menu (`showListHeaderMenu`, saved as `view/listColumns`, applied after `restoreState` by `applyListColumns`, since headers saved before had 4 columns). Names are looked up once per id. View → Sort lists only the first 4 columns.
      - Cut, Move to Trash, Delete, Rename and Move to Other Pane need `canChangeSelection()`: the exact `access(W_OK|X_OK)` on each selected item's folder (once per folder), and in sticky folders like /tmp only your own items. Copy always works. `IN_ATTRIB` makes a chmod update the row.
    - Sorting is done by the model: folders first (even when descending), then the sort column, then natural case-insensitive order (`QCollatorSortKey`). `resort()` keeps persistent indexes.
    - It watches only the open folder: inotify on Linux, so saved files (`IN_CLOSE_WRITE`) update too, and `QFileSystemWatcher` elsewhere. Changes are rescanned (debounced) and applied as minimal row inserts, removes and updates. More than 500 changes trigger a reset instead. `folderGone` fires if the folder disappears.
    - Sub-folder item counts ("12 items") are computed in the background.
    - Expandable folders (Preferences → List View, `view/expandFolders`, like Nautilus): a **flattened tree** in the same flat model, so selection, actions, drag and drop and rename work unchanged. `setTreeEnabled` / `isTreeActive()` (plain folders only: search, Trash, Recent and Starred stay flat; the grid turns it off via `setGridMode`). `expand(folder)` adds the folder to `m_dirs` and `m_expanded`, watches it (`addWatch`) and lists **only that folder** (`startChildScan` → `applyChildren`, inserted as one block right below it). `collapse` removes the block and every folder opened inside it. `sortTree()` sorts each folder's rows on their own and lays them out depth first; the batch merge in `resort(prefix)` is skipped while folders are open. Depth isn't stored: `depthOf()` counts the levels below `m_path`.
      - `applyRescan(…, scanned)` only touches rows of folders that listing read, so a rescan already running can't drop a folder opened meanwhile; opened folders that vanish are closed. `relist()` (new folder or search) closes everything. Hiding hidden files closes opened hidden folders.
      - Roles: `TreeDepthRole` (-1 = no tree), `ExpandedRole`, `ExpandableRole` (no arrow for "0 items"). `FileItemDelegate::treeIndent` / `expanderRect` place the ▸ arrow and indent the icon, name and rename field. `MainWindow::eventFilter` toggles on a click on the arrow (consumed, so it doesn't select or open), `handleTreeKey`: → opens, ← closes or goes to the parent folder.
    - Invariant: the path index (`m_rowByPath`, via `rebuildIndex()`) is marked stale **before** `endInsertRows`/`endRemoveRows`, because listeners such as paste-highlight call `indexForPath` from those signals.
  - **The list in columns** (Preferences → List View → Columns, `view/listColumnCount` 1–4, `MainWindow::setListColumnCountEverywhere`; `tst_mainwindow listInColumns`): a third view, `Pane::columnView` (a `QListView` in IconMode, LeftToRight, wrapping, sharing the one selection model) with `Pane::columnsDelegate` (`FileItemDelegate::setColumnsMode`: a cell is a list row of its own, icon, name, mark and the Size column's text at the right). `MainWindow::listView()` is the list the pane shows (`detailView` at 1, `columnView` above); `setGridMode(false)` goes to it. **A cell's width is what QListView lays out in**: `fitColumnCells` (on the viewport's resize and zoom) divides `maximumViewportSize().width()` less `PM_ScrollBarExtent` (Qt keeps room for a scrollbar when it wraps, shown or not) less one pixel; IconMode sizes an item by its **size hint**, so the delegate returns the view's `gridSize()`. Expandable folders are off while it is on. It uses the list's zoom.
  - There are two views in a `QStackedWidget`: `m_pane->iconView` (QListView, IconMode) for the grid and `m_pane->detailView` (QTreeView with columns and sortable headers) for the list. They share the proxy model and **one selection model**. `m_pane->view` points at the visible one.
    - Each view has its own `FileItemDelegate` (grid / list), because delegates cache sizes.
    - The table selects whole rows, so use `selectedViewIndexes()` (column 0 only) instead of `selectedIndexes()`.
    - Overlays (floating bar, progress card, toast) are children of the pane's `viewStack`.
  - `FileItemDelegate` paints every item itself: wrapped, middle-elided names, rounded hover/selection, list-mode size/date.
    - Zoom: `setIconSize(px)` from the levels `gridSizes()` (32…256) / `listSizes()` (16…48). It clears the wrap cache (keyed by name only) and the thumbnail cache, and emits `sizeHintChanged`, so views re-lay out without a reset and keep the selection.
    - `MainWindow::zoom(+1/-1/0)` / `applyZoom()` also update `iconView->setGridSize` and the zoom actions' limits. Ctrl+wheel on a file viewport adds up `angleDelta` and zooms per whole notch (touchpads). Saved as pixels in `view/gridIconSize` / `view/listIconSize`. Thumbnails are kept at up to 256 px (`Thumbnailer::MaxSize`).
  - `Thumbnailer` (in `argonaut_core`) loads thumbnails in a thread pool and emits `thumbnailReady`, which repaints the viewport. Requests come only from `FileItemDelegate::paintIcon`, i.e. visible items, with the **effective** mime (never for Dangerous files). Order: the freedesktop cache (`~/.cache/thumbnails/{large,x-large,normal,xx-large}`, checked against `Thumb::MTime`), then `QImageReader` for images, then on Linux a system thumbnailer.
    - Thumbnailers: `/usr/share/thumbnailers/*.thumbnailer` from every XDG data dir (first per type wins; TryExec must exist). Parsed by `readThumbnailerEntry`, **not QSettings**: QSettings treats `;` as a comment and would keep only the first MimeType. Exec placeholders: `%s` (256, `GenerateSize`), `%u`, `%i`, `%o`, `%%`.
    - They run on `m_external` (2 threads, `nice 10`, LIFO via a rising priority so the newest painted item goes first, 15 s timeout). `MainWindow::navigateTo` calls `cancelPending()`, which drops queued runs.
    - **Sandbox**: when `bwrap` exists, each run gets read-only `/usr`, `/etc`, font and GStreamer caches, `--unshare-all` (no network), its own `/tmp`, and only the one file, bound as `/tmp/gnome-desktop-file-to-thumbnail.<real suffix>` with output `/tmp/gnome-desktop-thumbnailer.png`. Those names matter: Ubuntu's AppArmor profiles (e.g. evince-thumbnailer) only allow these paths. `ARGONAUT_THUMBNAIL_SANDBOX=0` turns it off (tests with fake thumbnailers outside /usr).
    - Results are saved per the spec (PNG with `Thumb::URI`/`Thumb::MTime`/`Thumb::Size`, 0600, atomic rename) into `large/`, shared with Nautilus. Failures get a marker in `fail/argonaut/` until the file's mtime changes.
    - Policy (`thumbnails/generate`, Preferences): local disks only (default; not `needsSafeWrites` or `isNetworkFilesystem`, cached per folder), everywhere, or never (existing thumbnails only).
    - Measured: PDF ~60 ms, video ~140 ms per file in the sandbox. `tst_thumbnailer` covers parsing, caching, failure markers, policies and cancel with a fake thumbnailer, plus real sandboxed evince/totem runs when installed.
  - The views show `DirectoryModel` through `FileFilterProxy` (a `QSortFilterProxyModel`). Indexes from the view or selection are **proxy** indexes: convert them with `toSource()` / `toView()` before calling `m_pane->model->filePath`/`isDir`/etc. `FileItemDelegate` resolves through proxies itself.
  - Search (Ctrl+F) is done by the model, in sub-folders too: `DirectoryModel::setSearch(query)` re-lists (`relist()`) with the worker walking breadth-first from `m_path` and keeping only names that contain **all** words, ignoring case and accents (`foldForSearch`: NFD, drop non-spacing marks, case-fold; ASCII fast path in `matchesSearch`). So Greek "θαλασσα" finds "Θάλασσα".
    - The walk doesn't follow symlinks, stays on the starting drive (`st_dev`, so no `/proc` or mounted sticks) and skips hidden folders unless hidden files are shown (`setShowHidden` searches again). It stops at `MaxSearchResults` (10,000; `searchTruncated()`). In the Trash it only filters, without recursing.
    - Rows are keyed by full path, as in trash mode. The Type column becomes Location (`searchLocation`: relative to the searched folder), and the tooltip says "In …" for the grid. Content checks only read visible results (`m_thorough = false`).
    - Only the searched folder is watched, so `onJobFinished` calls `refresh()` in search mode; the rescan is another full search applied as a minimal diff.
    - `MainWindow` debounces typing by 150 ms (`m_searchTimer`); clearing is immediate. `setPath()` ends a search, and `navigateTo` blocks the search field's signals while leaving search, so the old folder isn't listed again. The floating bar shows "Searching… / N results / No results"; "Open Item Location" goes to a result's folder and selects it.
    - `FileFilterProxy` no longer filters. It never sorts either: `FileFilterProxy::sort` forwards to the model, so header clicks and View → Sort Files both sort `DirectoryModel`. Hidden files are filtered by the model (`setShowHidden`).
    - Read-only benchmark on a real home folder: same results as `find`, first results after ~17 ms, full walk ~2 s warm (`find`: 4.4 s).
- Split view (F3, `setSplitView`): one or two file panes in `m_paneSplitter`. **Each pane owns everything of its own** in `MainWindow::Pane` (`m_panes[2]`): `model`, `proxy`, `view`/`iconView`/`detailView`, `viewStack`, both delegates, `floatingBar`, `message`(`Timer`), `current`, `back`/`forward`, `grid`, the zoom levels, the pending selection/scroll/rename, Recent's sort. The window's code reaches all of it through **`m_pane`, the pane being worked on** (`m_pane->model`, `m_pane->current`…). There are no per-pane members on the window and nothing is copied when panes switch: a new per-pane field is one line in `Pane`.
  - `m_activePane` is the pane the user is in; `activatePane(i)` switches for good (it ends rename, search, Quick Look and Analyze, points `m_pane` at the pane, then `refreshChrome()`: path bar, title, sidebar, actions, view-mode buttons, captions). Input in the other pane (press, key, wheel, focus, context menu) activates it in `eventFilter`, *before* the normal handling, so shortcuts like Delete always act on the pane you're in.
  - `PaneScope(this, i)` points `m_pane` at pane `i` for the length of a block, for things that happen in the pane the user isn't in: its model loading, its selection changing, its folder vanishing (every connection made in `buildPane` captures the pane index), drags and drops onto it, its resize. - File operations (copy, cut/paste, move to trash, undo):
  - `FileJob` runs one operation on a worker thread (`FileOperations` owns a 2-thread pool). It first measures the total size, then transfers chunk by chunk, checking `cancel()`. Progress is a mutex-guarded snapshot (`progress()`); `progressChanged` is throttled and delivered queued.
  - Safety rules to keep:
    - Never overwrite: files open with `QIODevice::NewOnly`. When the destination name is taken, `transferItem` resolves the clash:
      - Copies into the item's own folder duplicate without asking.
      - Otherwise `askUser` emits `conflict(source, existing)` and the worker **waits** (`QWaitCondition`) until `resolveConflict()` or `cancel()`.
      - The answers are Replace (the existing item goes to the **Trash** first; it is never deleted), Skip, KeepBoth (`uniqueTargetPath` or a typed name), Merge (folder onto folder: `mergeInto` handles each child, asking again inside) and Cancel.
      - "Apply to all" is remembered separately for files and folders.
      - Only newly created items go into `results`, so undoing a merge never touches what was already there.
      - Jobs ask only when `FileOperations::setAskOnConflict(true)`; otherwise they keep both silently, which is the tests' default. `MainWindow` shows `ConflictDialog`s one at a time (`m_conflicts` queue).
    - A move tries `QDir::rename` first and falls back to copy and then delete; the original is deleted only after the copy is complete.
    - A cancelled or failed item removes only its own newly created target, and only if this job made something there (`m_createdTarget`): a name another program took in the meantime isn't ours to remove.
    - `copyTree` looks at each item with `lstat` (Unix): a symlink is copied as its **own text** (`readlink` + `symlink`, so `../lib/x` stays relative; `QFileInfo::symLinkTarget()` is absolute and `readSymLink()` needs Qt 6.6); a FIFO is re-made with `mkfifo` (opening one blocks forever, and Cancel can't interrupt `open`); sockets and device files are left out with an error on a copy and stop a move (so the original is never deleted without its copy). A folder that can't be listed is an error, not an empty copy.
    - Replace refuses when the source is inside the item it would replace (trashing the target would trash the source).
    - Removable drives (`needsSafeWrites`): on Linux these are udisks mounts under `/media` or `/run/media`, a USB sysfs path, or the sysfs `removable` flag; on macOS, `/Volumes/`. For those, data is flushed to the device every 32 MiB (`fdatasync`). The filesystem is synced (`syncfs`) before a cross-filesystem move deletes the source, and again at the end of the job. During that final sync the job shows `Progress::finishing` ("Writing to the drive…"), and the drive is listed in `flushedDrives()`. The internal disk is never synced, to keep it fast. `ARGONAUT_SAFE_WRITES=1/0` forces the behaviour (used by the tests).
  - `FileOperations` records each user action's `TransferResult`s on an undo stack. Undo runs the inverse job: a copy is undone by trashing the copies (never deleting them), a move by moving back, and a trash by `Restore`, which also removes the Linux `.trashinfo`.
    - Redo: `runInverse()` serves both directions. An entry stores the job that happened (`kind`, `results`) plus the user's original `action`/`name` for the menu text. When the inverse job finishes, *its* results become an entry on the other list. So redoing a copy restores the very copies the undo trashed (Restore's inverse is Trash), a move moves again, and a trash trashes again.
    - Any new action (`startJob` with `recordUndo`, or `recordUndo()`) clears `m_redo`. `recordUndo(kind, results, action)` takes a name ("Rename", "New Folder") and builds "Undo …"/"Redo …".
    - History jobs carry `HistoryProperty` ("undo"/"redo") so `onJobFinished` says "Undone"/"Redone".
    - **Connect to a job's `finished` before it starts** (`startJob`'s `prepare` hook): `finished` is emitted on the worker thread, and a quick job (one rename) can be done before `startJob()` returns, so a connection made afterwards is never called. `runInverse` did that once, and now and then an undo left nothing to redo (seen as rare "timed out waiting for a file job" in `tst_naming batchUndoAndRedo` and `tst_fileoperations redoTrash` on a busy disk).
  - Undo jobs are marked with the `UserActionProperty` dynamic property set to false, so `MainWindow::onJobFinished` treats them differently.
  - The clipboard uses `text/uri-list` plus the GNOME (`x-special/gnome-copied-files`), KDE (cut flag) and Windows ("Preferred DropEffect") formats, so it works with other file managers.
  - UI: `OperationsPanel` (bottom-left card) appears only for jobs running longer than 400 ms. `Toast` (bottom-centre, with an Undo button for trash) avoids the panel's rectangle.
- Archives (`src/FileJobArchive.cpp`, libarchive; `FileJob::Kind::Extract` / `Compress`, so they get the job engine's progress, cancel, USB safety and undo):
  - Extract unpacks each archive into a hidden `dest/.<base>.argonaut-extract` folder, then places it: exactly one top-level item is renamed out as is, otherwise the temporary folder becomes `<base>` (both via `uniqueTargetPath`, never overwriting). Cancel or failure removes the temporary folder.
  - Security: `isUnsafePath()` rejects absolute, `..` and drive-letter paths (and hardlink targets) and counts them in one warning; `ARCHIVE_EXTRACT_SECURE_SYMLINKS | SECURE_NODOTDOT` also apply. **Not** `SECURE_NOABSOLUTEPATHS`: every entry is rewritten to an absolute path inside the temporary folder.
  - `support_format_raw` handles plain `.gz`/`.xz`; the entry is named after the archive (`archiveBaseName`, which knows `.tar.gz` and friends). Progress is compressed bytes read (`archive_filter_bytes(a, -1)`). Encrypted archives give an error (no password support yet).
  - Compress writes all sources into `dir/.<name>.argonaut-part` and renames it when complete. The format (`ArchiveFormat`: zip with UTF-8 names, tar.gz / tar.xz as pax_restricted, 7z) goes through `FileOperations::m_pendingFormat` → `setArchiveFormat` before the job starts.

  - `tst_archives` covers round trips in every format, zip-slip/absolute/symlink escapes, placement, cancel (20k-entry tar, cancelled with a `DirectConnection` so it's deterministic), damaged archives and undo.

Only the shell can change its folder, so the line is still typed; `QuietCommand::begin` notes the cursor's row, the picture is held back (`setUpdatesEnabled(false)` in the widget; no `changed()` from the Shell), a 15 ms timer waits for `settled(done)` (the shell idle **in the target folder** and 60 ms without output, or 1.5 s), and `finish` feeds the emulator `CSI row H`, `CSI n M` (delete lines) and the cursor's new place: the rows the typed line took (the row noted, less what scrolled off since, plus the rows libvterm marks as its `continuation`). **Only those rows are ever removed, never what was there before, and nothing when the `cd` failed** (the shell's complaint stays) or the line has scrolled out. On the alternate screen without the mouse (less, man) the wheel is three arrow keys a notch, as GNOME Terminal does. A test that reads the terminal from a script needs `timeout --foreground` (plain `timeout` puts its command in the background, where reading the terminal stops it).

- Trash (Linux/BSD, freedesktop spec; `src/Trash.{h,cpp}`):
  - The home trash is `~/.local/share/Trash/{files,info}`. Other drives have `<root>/.Trash-<uid>` or `.Trash/<uid>`, whose `.trashinfo` `Path=` may be relative to the drive root.

Anyone can write to a USB stick: a `files` that linked to `~/Documents` would list that folder as trash, and Empty Trash would delete it. Keep these checks (`tst_fileoperations driveTrashRejectsLinks`).

- Install and default file manager (Linux):
  - `cmake --install` (the release preset's prefix is `~/.local`) installs the binary, `argonaut.desktop` (from `data/argonaut.desktop.in`, with the **absolute** binary path because D-Bus and the shell don't use the user's PATH) and `data/argonaut.svg`. The previous default is saved in `system/previousFileManager` and restored (Nautilus if it's gone). It never overwrites or removes a service file it didn't write (`Marker`).
  - `FileManagerService` (core, Qt DBus, `ARGONAUT_DBUS`): ShowFolders/ShowItems/ShowItemProperties become signals with local paths. Only `argonaut --service` takes the name; it opens a `WA_DeleteOnClose` MainWindow per request (`openFolders`/`showItems`) and passes the StartupId as `XDG_ACTIVATION_TOKEN`/`DESKTOP_STARTUP_ID`.
    - **It stays running while Argonaut is the default.** Nautilus asks for `FileManager1` whenever it runs (Ubuntu's desktop icons, DING in gnome-shell, start it in the background) and waits in line if it's taken; a service that quit after its last window handed "Show in folder" to Nautilus. So `--service` sets `setQuitOnLastWindowClosed(false)`, asks with `IfTaken::WaitInLine` (`QueueService`; `nameAcquired` when Nautilus lets go), exits at once if another `argonaut --service` owns or waits for the name (`anotherServiceRuns`: `ListQueuedOwners` + `/proc/<pid>/exe`), and quits only when our service file is gone (checked every 10 s) and no window is open.
    - `DefaultFileManager::startService()` starts it right after Preferences or `--make-default` makes Argonaut the default (not from `makeDefault()` itself, so tests start nothing). `tst_fmservice waitsInLine` covers the queue.
  - `main()` handles `--make-default` / `--restore-nautilus` **before** creating a QApplication (they work without a display). Positional arguments: folders open (the rest in tabs); files are shown selected in their folder.
  - **`tst_fmservice` runs only under `dbus-run-session`** (ctest sets `ARGONAUT_PRIVATE_BUS=1`) and refuses a bus that has `org.gnome.Shell`: taking the name on the desktop's bus would steal "Show in folder" from Nautilus. Call the service asynchronously and without QDBusInterface (which introspects synchronously), or the test deadlocks on itself.
- Open/Save windows for other apps (Linux, `ARGONAUT_DBUS`; opt-in): Argonaut is an xdg-desktop-portal **FileChooser backend**.
  - `ChooserRequest` (core, `src/FileChooserRequest.{h,cpp}`) decodes the portal's `a{sv}` options (filters `a(sa(us))`, choices `a(ssa(ss)s)`, NUL-terminated `ay` paths; registered D-Bus types `Portal*`) and builds the results (`uris`, `choices`, `current_filter`, `writable`). `Filter::matches` takes globs case-insensitively and mime types by inheritance (`image/*` too).

  - `argonaut --portal` (main.cpp, D-Bus-activated through `org.freedesktop.impl.portal.desktop.argonaut.service`) makes one `MainWindow` per request. The behaviour described below lives in `ChooserMode`; `MainWindow::startChooser()` creates it and only hides the menus, terminal/Analyze/split/menu buttons and turns off commands that open other windows or quit (`ChooserMode::setUnavailableActions`, kept off by `keepActionsOff` after every action update), adds a `ChooserBar` (name field for Save, choices, filter combo, Cancel/accept) and sets `FileFilterProxy::setChooserFilter` (folders always shown; a folder picker shows only folders). `openIndex`/`openSelection` accept instead of opening apps; Esc (`keyPressEvent`) and closing cancel; `chooserFinished(response, results)` answers once. Its settings aren't saved (`closeEvent` returns early); only `chooser/size` (not the position: it opens centred on the screen with the mouse, since GNOME centres only modal dialogs and Qt can't read a foreign window's geometry) and `chooser/lastFolder/<appId>`. X11 parents (`x11:<hex>`): `ChooserMode::attachToParent()` writes `WM_TRANSIENT_FOR` onto the window **with xcb** (`ARGONAUT_XCB`, optional `pkg-config xcb`; `QNativeInterface::QX11Application`), from `showEvent` + a zero timer. Qt can't do it: its xcb plugin sets the property only for dialog-type windows and deletes it in `show()` for others, and a `Qt::Dialog` window can't be minimised or maximised under mutter (any non-normal type). Without the property the window dropped behind the app whenever the app came forward. It is not modal: GNOME attaches modal dialogs to their parent (`attach-modal-dialogs`) and they can't be moved. The "Replace?" question runs a nested loop, so it's guarded (`ChooserMode::m_asking`, `QPointer` self): the app's Close can delete the window meanwhile. The service quits after 5 idle minutes.
  - `PortalConfig` (core) is the switch (Preferences → Open and Save Windows): it writes `~/.config/xdg-desktop-portal/<first desktop>-portals.conf` (here `ubuntu-portals.conf`) with a UTF-8 marker, the `[preferred]` lines of the file in effect plus `org.freedesktop.impl.portal.FileChooser=argonaut;`, never touches a file it didn't write, and restarts the portal (`systemctl --user try-restart xdg-desktop-portal.service`, `ARGONAUT_SYSTEMCTL_PROGRAM` in tests). **xdg-desktop-portal 1.18 reads backends only from `/usr/share/xdg-desktop-portal/portals`** (or `XDG_DESKTOP_PORTAL_DIR`), so it works from the .deb, not a `~/.local` install; `data/argonaut.portal` has no `UseIn`, so it's never picked unless configured.
  - `tst_filechooser` (under `dbus-run-session`) covers decoding with the portal's real wire types, delayed replies, Close, filters and the config switch in a sandboxed XDG tree.

- Extensions (`src/Extensions.{h,cpp}`, core; `tst_extensions`; `docs/extensions.md` is the guide for authors and **the protocol is a public promise**: add keys and message types, never change or remove what version 1 has): separate programs, any language, one process per switched-on extension for the whole app, JSON lines on stdin/stdout.

- **The sandbox needs an AppArmor profile on Ubuntu 24.04 and later** (`data/apparmor/argonaut-files`, installed by the package as `/etc/apparmor.d/argonaut-files`, loaded by `data/debian/postinst`, a conffile).   - Opening a file (Enter, a double click; `App::openFile`): the real type first (`ContentType`, the same cache as the window), **a Dangerous file is never opened**; with a desktop (`DISPLAY`/`WAYLAND_DISPLAY`) the default app for the effective mime through `OpenWith` (`gio`, so `ARGONAUT_GIO_PROGRAM` fakes it; not `QDesktopServices`, there is no GUI platform), and `RecentFiles::add`; without one a textual file is shown in the terminal and anything else can't be opened. The App only emits `viewRequested(path)`; `Run.cpp` hands the terminal to `less` (`Terminal::suspend`/`resume`) with **`LESSOPEN`/`LESSCLOSE` removed and `LESSSECURE=1`**, so no helper program runs on the file and nothing can be started from the pager. `tst_tui opensFiles`.
  - Shell panel (**F12**, and Ctrl+`, which a terminal sends as NUL, the same byte as Ctrl+Space; `Terminal` turns it into `Key::control('`')`): `Tui::Shell` (`Shell.{h,cpp}`, in `argonaut_tui`, needs libvterm: `ARGONAUT_TUI_SHELL`) runs `$SHELL` on a pty, prepared before `forkpty` like `TerminalWidget`, and keeps libvterm's screen; `draw()` copies its cells into the `Screen` as **raw** cells (`Style::raw` with `fg`/`bg` = one of the terminal's 256 colours, `underline`, `reverse`; RGB becomes the nearest), which `Terminal::rawPair` gives ncurses colour pairs on demand. `Shell::key` turns a `Key` back into bytes with `vterm_keyboard_*`, so cursor-key modes are right. The panel is the lower third or so (35%, `shellHeightFor`) **of the files' area** (`drawShell(screen, x, …)`: from `m_shellX`, right of the places, which keep their whole height as the window's sidebar does; a title line with the shell's folder, then the cells; resized from `render`). `App::key` (Normal mode): F12/Ctrl+` → `toggleShell` (the first time it starts the shell in the pane's folder, home for a place; after that it switches `m_inShell`), and while `m_inShell` **every other key goes to the shell** (so `q`, F8, Delete do nothing to the files; the key line shows only "F12 Files"), except Ctrl+Up, which brings the active pane to the shell's folder as in the window. A question (name clash) still gets the keys, since modes come first. A click on the panel or on a pane moves the typing there. The shell ending (`exit`) closes the panel (`closeShell`, queued); programs in the shell don't get the mouse. **Scrollback** (`tst_tui shellPanelLooksBack`): `sb_pushline` keeps the lines that leave the top (`Shell::MaxHistory` = 5000, as libvterm's own cells; `sb_popline` gives the newest back when the panel grows), `scrollBack(lines)` / `scrolledBack()` / `historySize()`; `draw` then shows kept lines above the screen's first rows and `cursor()` is false once it is pushed out of the panel. New output while looking back doesn't move what is shown (`m_back` grows with it); any key typed goes to the newest; while a program has the alternate screen (`VTERM_PROP_ALTSCREEN`: a pager, an editor) there is nothing to look back at. In the App: the wheel over the panel (3 lines), Shift+PgUp/PgDn (`KEY_SPREVIOUS`/`KEY_SNEXT`, where the terminal passes them on; GNOME Terminal keeps them for its own scrollback outside the alternate screen), and a scrollbar in the panel's last column (`m_shellBarX`, **always reserved**, so the shell's width doesn't change when the first line scrolls off; a click on it: top = oldest, bottom = newest). The title line says "N lines back". `Terminal` also reads arrows/Home/End with Shift, Alt or Ctrl now (`key_defined`/`define_key` on xterm's `ESC [ 1 ; n X`), so Alt+Left and Ctrl+Up arrive. Without libvterm (`setEmbeddedShell(false)` in tests) F12 emits `shellRequested(folder)` and `Run.cpp` gives the whole terminal to `$SHELL` (`suspend`/`resume`, like the pager), then `App::shellClosed(lastFolder)`. `tst_tui shellPanel` (a real `/bin/sh` on a pty), `shellInTheFolder`.
  - **Selecting with a rectangle** (`App::startBand` / `bandTo` / `updateBand` / `endBand` / `drawBand`, `App::Band`; `tst_tui rectangleSelects`, and the smoke test drags in a real pseudo-terminal): `Mouse` has `Release` and `ctrl` now. A press on the files starts a band (`m_band.down`); a `Move` while it is down goes to `bandTo` instead of `hoverAt`; once the mouse is on another item than the press (`active`) the selection is what the rectangle covers, from the anchor to the mouse: rows in a list, cells in the grid and the big icons (`..` never). **The anchor is a line and column of items, not of the screen**, so the list can scroll under it: past the top or bottom the cursor goes one line further each 70 ms (`m_bandTimer`), and it is the next frame's "keep the cursor in sight" that scrolls. Ctrl+click toggles one item, Ctrl+drag adds to the selection (`Band::base`), a click on empty space clears it (as in the window; a plain click on an item still only moves the cursor). The rectangle is drawn as `Paper::Hover` under what it covers (`Screen::tint`). `Terminal`: `BUTTON1_RELEASED` and `BUTTON_CTRL` are in the mouse mask, **a move is told before a press** (ncurses may report the held button with it), and `ESC[?1002h` (button-event tracking) is sent whatever the effects are (`setDragging`; ncurses itself asks only for presses and releases), off again at exit and on suspend. A terminal keeps Shift+drag for its own text selection.
  - **Copy, cut and paste** (Ctrl+C / Ctrl+X / Ctrl+V; Edit menu, right-click menu, palette; `App::copyTargets`, `paste`, `forgetClipboard`; `tst_tui copyCutAndPaste`, `clipboardSharedWithTheDesktop`): the terminal interface has no `QClipboard` (it runs on the offscreen platform), so `src/FileClipboard.{h,cpp}` (core) is its clipboard: `encode` / `decode` of `x-special/gnome-copied-files` (the format `FileOperations::setClipboardFiles` writes, so the window and Nautilus understand it; only local absolute paths come out of `decode`) and the desktop's clipboard through a helper program, `wl-copy`/`wl-paste` under Wayland or `xclip` under X11 (`xsel` can't offer a kind other than text), each run to the end with a 1.5 s limit. The App always keeps what was copied itself (`m_clipPaths`, `m_clipCut`); `paste` asks the desktop first (`readDesktop`: `Files` → those; `Empty` → another program copied something else, ours is forgotten; `Unavailable` → ours), drops paths that are gone, needs `FileRules::isTransferTarget` and `transferProblem`, then `m_ops->copy` / `move` (so progress, the name-clash question and undo). **A cut is pasted once** (`forgetClipboard` + `clearDesktop`), cut items are drawn in `Ink::Dim` in all three views (`m_cutShown`) and Esc with nothing selected forgets the cut. **Off in tests**: `ARGONAUT_CLIPBOARD=0/1`, unset it is off wherever `ARGONAUT_TRASH_HOME_ONLY` is set, so no test reads or writes the real clipboard; `ARGONAUT_CLIPBOARD_PROGRAM` is a pretend xclip. The package recommends `xclip | wl-clipboard`.
  - **Forms, plans and Claude in the terminal** (`src/tui/AppDialogs.cpp`, a part of `Tui::App`; `tst_tui extensionFormInABox`, `extensionPlanIsTickedAndApplied`, `waitingForClaudeIsSaid`, `claudeKeyIsTypedAsDots`): so Organize with Claude and Connect to Server work here. `formArrived` / `planArrived` (queued from the host's signals) take one only when nothing else is being answered (`roomForABox`: a menu, the palette or the help gives way; a question is answered first, they try again 300 ms later), with the host's own `takeForm` / `takePlan`, so its rules (only for what the user chose, one at a time) hold here too.
    - `Mode::Form` (`drawForm`, `formKey`, `mouseInForm`): a box that **always names its extension** in the frame; the keys go round `formStops()` (the fields that are on, then the form's buttons, then Cancel: Tab, Up/Down); Space or Left/Right change a tick or a choice; PgDn/PgUp go through a text field's suggestions; Enter on a field goes to the next and from the last presses the first button; Esc cancels. **A secret is drawn as dots** and the values are cleared when the box closes. A tick that is `alone` takes the other fields out of the stops. A click on a field goes to it, on a button presses it, beside the box does nothing.
    - `Mode::Plan` (`drawPlan`, `planKey`, `mouseInPlan`): the report read as text (`reportLines`: headings without marks, no pictures or link targets), then a line a move, `[x] name → Folder/new name` and the reason; a move with a `problem` is `[!]`, red, and **can't be ticked**. Space ticks, `a` all or none, Enter → `closePlan(true)` → `PlanApply::run`, Esc → `answerPlan(dismissed)`. The wheel scrolls; a click on a move changes its tick.
    - Waiting for Claude: `Host::claudeWaiting` → the message line ("“Organize with Claude” is asking Claude… 12 s (Esc stops waiting)", `statusText`, a one-second timer); Esc with no job running → `Host::stopWaitingForClaude`.
    - **Edit → Claude API Key…** (`setClaudeKey`): a prompt with `m_promptSecret` (dots) → `KeyStore::save`; with `ANTHROPIC_API_KEY` set it only says that one is used. On a server without the window this is the only place to enter it.
  - `tst_tui` (42 tests, links `argonaut_tui`, no terminal): the screen's text, navigation, selection, F5/F6 with undo/redo, trash and undo, permanent delete and delete-in-Trash ask and only `y` goes ahead (**verified by breaking the check**), a read-only folder, new folder and rename (never onto an existing item), name clashes, hidden files, go-to, quit. `tests/tui_smoke.py` (ctest `tui_smoke`) starts the real program in a pseudo-terminal and checks it draws, shows the help and gives the terminal back on F10: the only test of the ncurses layer.
- Search filters (`DirectoryModel::setSearchFilters`, `passesFilters`; the "Filters" button): type (by name's mime) and date (mtime). `isSearch()` is true with filters alone, so they search the tree without words; `setSearchActive(false)` clears them.
- There is no status bar. Each pane's `floatingBar` (a `QLabel` over the view) shows selection info and temporary messages (`showMessage`).
